# User standing defaults

These are user-authoritative career-workflow defaults, confirmed on 2026-09-16. Apply them without asking again until the user explicitly changes one. A newer explicit instruction always wins.

## Application defaults

- **Salary:** enter `Negotiable` when a free-text salary answer is required. Do not provide a numeric range unless the user explicitly changes this preference. If the site requires a numeric value, mark the field as needing user input instead of inventing one.
- **AI interview note-taking:** select `Yes, I consent` only when the question is specifically about an AI assistant taking notes during an interview. Do not extend this default to unrelated recording, biometric, privacy, model-training, data-retention, or general AI consent.
- **Accuracy and completeness:** select `Yes` for an acknowledgement limited to the accuracy or completeness of application materials, after checking that the materials are factual.
- **EEO:** choose an offered decline-to-answer or do-not-wish-to-answer option. If an optional EEO field has no decline option, leave it blank; do not substitute a factual answer.
- **Resume:** use the verified `Ye Xinnan Resume - 2026.pdf`. Confirm the exact file identity before upload and read back the visible filename after upload.
- **Final actions:** the user clicks application `Submit` and LinkedIn `Send`. Filling, uploading, opening a composer, or completing verification never authorizes either final action. Only a later explicit instruction for the exact action changes this.

## Reuse and invalidation

Reuse these defaults across roles and turns while they remain in the active context. Do not reopen a page merely to reconfirm them. Re-read this reference when starting a new career workflow session or after context compaction, and replace a default only when the user gives a newer explicit instruction.
